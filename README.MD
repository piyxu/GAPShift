# GAPShift

Error handling in the code has been temporarily disabled, so the system may not behave as expected in some cases.  
Some commands may not function correctly, as the code is still in the testing phase.  
This README.md file was generated with the assistance of ChatGPT.

GAPShift is an experimental reversible transformation for fixed-width integer blocks.

This README describes the current **experimental self-sum metadata branch**. The code is still for testing. GAPShift is not an encryption system and it is not a standard compression algorithm. It is a reversible numeric-space transformation experiment.

---

## Current experimental status

The current branch changes the older metadata model substantially:

- `metadata.txt` is **not used**.
- Repeat passes use the **normal view only**; the previous even-repeat inverted view is disabled.
- Metadata is embedded with a **self-sum metadata model**.
- `-b` controls the starting block bit width.
- `-c` controls the generated random block count.
- Repeat mode writes only the **final repeat output** and final debug reports.
- `bits.txt` is written after the final encode/repeat result.

Default values are still:

```text
BIT_WIDTH = 4096
COUNT     = 1000
```

But they can now be overridden:

```bash
program -b 256 -c 1000
```

## Command line usage

```text
program [-b <bit_width>] [-c <count>]
program [-b <bit_width>] [-c <count>] -e <source_bits_file> <encoded_output_file>
program [-b <bit_width>] [-c <count>] -r <source_bits_file> <encoded_output_file>
program [-b <bit_width>] [-c <count>] -r <repeat_count> <source_bits_file> <encoded_output_file>
program [-b <bit_width>] [-c <count>] -d <source_bits_file> <decoded_output_file>
```

Examples:

```bash
program -b 256 -c 1000
program -b 256 -c 1000 -r input.txt output.txt
program -b 256 -c 1000 -r 20 input.txt output.txt
program -d output.20.txt decoded.txt
```

If `-b` is omitted for `-e`, `-r`, or `-d`, the program attempts to detect the bit width from the first non-empty line of the input file.

## Files produced

### `input.txt`

Random unique input blocks generated by the no-argument mode.

### `encode.txt`

Single-pass encoded output generated by the no-argument mode.

### `<name>.<repeat>.txt`

Final repeat output. Intermediate repeat outputs are kept in memory and are not written.

Example:

```text
output.20.txt
```

### `space.txt`

Detailed final debug record. In repeat mode this file is written only for the final successful repeat.

### `gap.txt`

Final selected source-pair and GAP debug report. In repeat mode this file is written only for the final successful repeat.

### `smallest_two_outputs.txt`

Final inspection report for the two smallest encoded outputs. In repeat mode this file is written only for the final successful repeat.

### `bits.txt`

Final leading-ones report. After each successful repeat, the program records the largest encoded value and counts how many leading `1` bits it has.

Examples:

```text
1110...  -> 3
11110... -> 4
0111...  -> 0
```

At the bottom of `bits.txt`, the minimum and maximum leading-one counts across repeats are reported.

### `metadata.txt`

Not used in this experimental branch. The program removes stale `metadata.txt` at the beginning of encode/repeat runs so decode does not depend on external overflow metadata.

## Core GAPShift transform

The algorithm works around one value called **GAP**.

For each encode pass:

1. Blocks are sorted in memory.
2. The closest adjacent pair is found.
3. The raw distance is computed:

```text
raw_gap = sorted[i + 1] - sorted[i]
```

4. The operational GAP is:

```text
GAP = raw_gap - 2
```

5. Each sorted block is shifted by its rank:

```text
shift(rank) = (rank + 1) * GAP
```

6. The encoded value is:

```text
y = x - shift(rank)
```

The `raw_gap - 2` rule makes the selected source pair differ by exactly `2` after encoding. This gives the decoder the recovery anchor:

```text
old_low_output = high_output - 2
```

## Repeat view mode

This branch uses the **normal view for every repeat**.

```text
repeat 1: normal view
repeat 2: normal view
repeat 3: normal view
repeat 4: normal view
...
```

The previous alternating inverted view is disabled in this experimental branch.

## Self-sum metadata model

The older metadata model stored:

```text
metadata_host_index + companion_index + GAP
```

inside a metadata host block, and used `metadata.txt` if GAP overflowed.

This branch removes both of those behaviors.

The metadata host does **not** store its own position. It also is **not** moved to slot `0`.

Instead, the metadata payload stores only:

```text
companion_index + GAP
```

using a mixed-radix integer:

```text
metadata_block = GAP * COUNT + companion_index
```

Then this metadata block is added to the largest encoded output value that is not the metadata host:

```text
metadata_host_new = largest_non_host_output + metadata_block
```

The metadata host remains in its original output slot.

---

## Self-sum decode model

During decode:

1. The largest output value is treated as the metadata host.
2. The next-largest output value is treated as the additive base.
3. The metadata block is recovered by subtraction:

```text
metadata_block = largest_output - second_largest_output
```

4. The metadata block is unpacked:

```text
companion_index = metadata_block % COUNT
GAP             = metadata_block / COUNT
```

5. The original overwritten metadata-host output is restored using the selected companion:

```text
old_low_output = companion_output - 2
```

6. Rank-based shifts are reversed to recover the original block set.

---

## Dynamic working width

Because self-sum metadata can make one block wider than the initial `-b` bit width, repeat mode may need a wider working width after later passes.

The experimental branch tracks an active working width:

```text
active_width = max(configured_bit_width, largest_current_value_bits)
```

Final output files are written with enough width to represent the largest value in that final output set.

This is an experimental behavior. If exact fixed-width output is required, the self-sum overflow check should be re-enabled or a bounded metadata carrier should be used.

## Repeat encode

Repeat mode can run until the transformation reaches a stopping condition:

```bash
program -r <source_bits_file> <encoded_output_file>
```

Example:

```bash
program -b 256 -c 1000 -r input.txt output.txt
```

If the last successful repeat is `20`, only the final repeat file is written:

```text
output.20.txt
```

Intermediate repeat files are not written.

A fixed repeat count can also be requested:

```bash
program -r <repeat_count> <source_bits_file> <encoded_output_file>
```

Example:

```bash
program -b 256 -c 1000 -r 20 input.txt output.txt
```

---

## Repeat decode

Repeat decode uses the repeat number embedded in the filename:

```bash
program -d <repeat_encoded_file> <decoded_output_file>
```

Example:

```bash
program -d output.20.txt decoded.txt
```

The decoder sees `.20.` in the filename and runs passes backward:

```text
repeat 20
repeat 19
...
repeat 2
repeat 1
```

This branch does not require `metadata.txt` for decode.

## Normal encode

Without arguments, the program generates random unique input blocks and writes:

```text
input.txt
encode.txt
```

Example:

```bash
program -b 256 -c 1000
```

You can also encode a specific source file:

```bash
program -e <source_bits_file> <encoded_output_file>
```

Example:

```bash
program -b 256 -c 1000 -e input.txt encode.txt
```

---

## Normal decode

Single-pass decode:

```bash
program -d encode.txt decoded.txt
```

If the source filename does not contain a repeat number, decode assumes one pass.

---

## Stopping conditions

A repeat chain can stop when:

- a safe closest-pair GAP cannot be produced,
- `raw_gap <= 2`,
- rank-based shifting would underflow,
- or the experimental self-sum metadata ordering cannot be decoded safely.

In this branch, external metadata overflow is not written to `metadata.txt`.

The program prints compact entropy statistics from in-memory vectors:

```text

```

The report includes:

```text
entropy bits/bit
ones count

one percentage

```

## Proximity report

The program prints proximity statistics:

```text
min_gap
min_gap/range
avg_gap
avg_gap/range
distance to zero
distance to top
distance ratios
```

The range is based on the active working width:

```text
0 .. 2^active_width - 1
```

## Reversibility

The design goal is exact recovery.

A successful encode pass performs an internal pre-decode check and prints:

```text
Reversible: true
```

For external validation, compare hashes of the original and decoded files.

PowerShell example:

```powershell
Compare-Object (Get-FileHash input.txt) (Get-FileHash decoded.txt) -Property Hash
```

An empty result means the files match exactly.

## What GAPShift is and is not

GAPShift is:

- deterministic,
- reversible when all safety conditions hold,
- metadata-aware,
- suitable for numeric-space transformation experiments,
- able to repeat-transform data while preserving a decode path.

GAPShift is not:

- encryption,
- a hash function,
- a security primitive,
- or a standard compression method.

It reorganizes numeric structure while attempting to preserve exact recoverability.

---

## Limitations

- This is an experimental branch.
- The self-sum metadata model depends on the largest and second-largest encoded values being recoverable and unambiguous.
- Self-sum metadata may increase the active output width if overflow control is disabled.
- A safe closest-pair GAP must exist.
- Rank-based shifting must not underflow.
- Decode needs the final repeat file.
- `metadata.txt` is intentionally not used in this branch.
- Debug reports can be large when `space.txt` is enabled.
